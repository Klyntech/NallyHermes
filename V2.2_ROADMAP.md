# NallyHermes V2.2 Roadmap — Historical Status

> **Status note (2026-11-14):** This document began as a forward-looking V2.2 roadmap. The `v3.1-Emotions` branch now contains substantial work from that plan. This file is retained to preserve the original direction, but the status below supersedes the original alpha.1 wording. The current branch is not a tagged v3.1 release.

## Release intent

V2.2 aimed to extend Nally's custom orchestra into a more capable personal operating companion: adaptive work selection, coding assistance, general assistance, law-student support, typed active memory, and Notion, Gmail and NallPuter connectors. The design constraint remains: no third-party agent framework, no unrestricted shell, per-user scope, explicit approval and bounded execution.

## Architecture constraints retained

- The model interprets intent; deterministic code enforces schemas, permissions, budgets and execution.
- Ordinary conversation and simple actions should not invoke unnecessary planning.
- Read-only work may run concurrently within configured limits; mutations remain sequential.
- Background workflow policy cannot silently approve an interactive mutation.
- External content from email, Notion, GitHub, files, PDFs and web pages is untrusted data.
- A provider is unavailable until its credentials and required configuration are present.
- A completed action must be supported by a tool result; partial work must be labeled as partial.

## Remaining roadmap

### 1. Coding workflow completion
- Add bounded diff previews and explicit changed-file summaries.
- Record commands, working directories, outputs and validation evidence.
- Add rollback/patch-reversal support where safe.
- Define a stronger remote-kernel authentication contract before enabling NallPuter for untrusted deployments.
- Keep command, package-install, network and service-restart permissions independently controlled.

### 2. Student Companion completion
- Add grounded document retrieval with page/source references.
- Build case briefs with facts, issue, rule, application, holding and significance.
- Add statute/section extraction with source context.
- Add IRAC/problem-question support that distinguishes source facts from explanation.
- Add timetable-aware revision planning, assessment deadlines and spaced review.

### 3. Memory and orchestra hardening
- Expand conflict resolution and explicit correction handling.
- Add durable execution resume state for interrupted multi-step tasks.
- Improve connector health/latency telemetry and budget-aware degradation.
- Add broader evaluation fixtures for routing, claim audit, tool selection and partial completion.
- Confirm privacy, expiry and user controls for every typed memory category.

### 4. Research quality
- Add a golden research evaluation harness to CI.
- Improve evidence presentation beyond rich-message formatting.
- Add targeted evaluation for primary-source selection, freshness, quantitative claims and citation completeness.

## Release discipline

The roadmap status is not a release certification. Before a stable release, use [docs/release-checklist.md](docs/release-checklist.md), run the build and tests on the intended commit, exercise configured integrations in staging, review the security boundary for NallPuter, and align the package version, changelog and release tag.
